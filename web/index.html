What BondWatch is

A read-only monitor for the parameters a Bitcoin staker is exposed to after their bond is locked. Everything on this page is fetched live from Stacks mainnet in your browser. There is no backend, no wallet connection, and no privileged access — you can reproduce every number yourself.

The problem it watches

PoX-5 (SIP-045) settles staking rewards trustlessly — that part needs no trust. The risk sits in the mutable parameters around a bond, which can change while a staker is locked in and cannot exit:

  • An irreversible pause. pause-admin can call pause-rewards. The contract contains no code path that sets the flag back — the only writer sets it to true. Once fired it cannot be undone without a hard fork.
  • Concentrated admin power. bond-admin can rotate who holds the admin roles. On mainnet today one principal holds both roles, so a single key can rotate the admin set and trigger the permanent pause.
  • Per-pool fees. Each pool runs its own signer-manager contract that decides for itself whether its fee can change, by how much, and how quickly.

Why per-pool detail is the point

A generic "watch for update-fees" rule gives false comfort, because the real managers do not share a mechanism. BondWatch reads each contract's deployed interface and applies that contract's rules:

Fast Pool
Caps fees at 5% and delays changes by two cycles — but applies a queued rate automatically when its cycle arrives, without writing it back. Read the fee variable alone and you get a stale number forever.
Xverse
Permits up to 100% — an effectively uncapped fee that can be changed at will.
Juice Pool
Caps at 20%, and a change is only a proposal until an admin confirms it after a 144-block cooldown.
Native Pool
Exposes no on-chain fee surface at all, so its terms are set off-chain and cannot be verified here.

That is why the fee shown is the rate actually charged right now, resolved against the current reward cycle, rather than whatever the contract's fee variable happens to say.

Reading the badges

  • Capped + delayed A low ceiling and a delay before changes take effect.
  • Fee increase scheduled A higher rate is queued and will apply on its own.
  • Fee can be raised without limit The operator can change the fee with no effective ceiling.
  • No on-chain fee Nothing to verify on-chain; terms live elsewhere.

How to check it yourself

Every value comes from public, unauthenticated node endpoints. For example, the protocol's pause flag: 

curl https://api.hiro.so/v2/data_var/SP000000000000000000002Q6VF78\
/pox-5/rewards-paused?proof=0

0x04 is false, 0x03 is true. Contract addresses on the cards link to the explorer. Method and verification trail are in FINDINGS.md.
